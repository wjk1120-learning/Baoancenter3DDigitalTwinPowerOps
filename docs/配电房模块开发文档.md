# 配电房模块开发文档

> 适用项目：Baoancenter3DDigitalTwinPowerOps（宝安中心医院 3D 孪生平台）
> 蓝本：福永项目（../Fuyong3DDigitalTwinPowerOps）
> 更新：2026-10-28

## 一、模块概述

在 3D 页面里还原医院各配电房：柜体按真实排布摆放，柜子可点击查看详情，告警柜子发光变色。数据分两份——**摆放和档案是前端配置（静态），实时状态来自后端（动态）**，靠设备编号（devCode，宝安 BZ 前缀）对接。

## 二、模块组成与现状

| # | 零件 | 说明 | 现状 |
|---|---|---|---|
| ① | 柜体模型 | 4 种 GLB（进线柜/配电柜/电容柜/双电源切换柜；kaiguan.glb 是二级开关单元模型，非柜体类型） | ⚠️ 需宝安中心医院制作（开发期用福永模型当替身） |
| ② | 配置文件 | src/config/power-rooms.json（哪个房、哪些柜、怎么排） | ✅ schema 已定，含福永 g2 真实数据 |
| ③ | 布局算法 | src/power-room/layout.mjs（排号定前后、顺序定左右、柜距 1.32m） | ✅ 已与旧项目对答案通过（10 柜坐标逐位一致） |
| ④ | 3D 场景 | 加载 GLB、按坐标摆放、灯光材质 | ⬜ 从旧项目 engine/ 搬迁改造 |
| ⑤ | 数据联动 | devCode 查后端；告警柜半透明呼吸光罩（不涂柜身） | ⬜ 从旧项目搬，依赖后端联调 |
| ⑥ | 交互 | 点击柜子开详情、视角控制 | ⬜ 从旧项目搬 |

## 三、前置准备清单（三件事并行，互不阻塞）

### 1. 柜体模型制作（周期最长，最先启动）

- **谁**：美术外包 / 建模人员
- **要什么**：照福永 4 种柜体规格做宝安中心医院柜型，导出 **GLB + Draco 压缩**
- **参考物**：福永模型在 `Fuyong3DDigitalTwinPowerOps/public/modelskaiguan/`（jinxian / peidiangui / dianrongui / shaungdianyaun / kaiguan 共 46MB，含解码器 public/draco/）
- **替换方式**：新模型同名放入 `public/models/cabinets/`，代码零改动（model 字段只认 5 个名字）
- **若宝安中心医院柜型超过 4 种**：扩 `schema/powerRoom.ts` 的 CabinetModel 枚举 + 校验脚本 MODELS 列表，同步做新模型

### 2. 甲方资料（决定配置内容）

| 资料 | 用途 | 找谁 |
|---|---|---|
| 设备台账 Excel（含设备编号） devCode 来源，挂实时数据全靠它 | 医院后勤/设备科 |
| 配电系统图 / 竣工图 | 决定每个房几排、每排柜子顺序 | 甲方 / 设计院 |

**配置生成流程**（资料到手后）：

```
发现场模板：docs/配电房摆柜信息采集表.xlsx（含填写说明+福永真实示例；
           需要改版时跑 python scripts/gen-cabinet-template.py 重新生成）
  → 现场按系统图填写（柜体类型中文下拉、排/位从 1 起、FY 编号照抄台账）
  → scripts/excel-to-rooms.mjs 转换（待开发：中文类型→model 枚举、排/位→rows、按房分组）
  → src/config/power-rooms.json
  → node scripts/check-power-rooms.mjs 校验把关
```

## 五、配置文件说明（power-rooms.json）

```jsonc
{
  "pitch": 1.32,                    // 柜间距（米）
  "rooms": [{
    "id": "g2",                     // 房 id
    "name": "新大楼配电房2#",
    "rows": [                       // 每排一个数组，排内从左到右
      [{ "code": "2AA1", "name": "2AA1 进线柜",
         "spec": "400V进线及计量柜",
         "model": "jinxian",        // 4 种柜体之一，显式指定
         "devCode": "BZ000001",      // 挂后端实时数据的编号，可空
         "nudgeX": 0,               // 单柜左右微调（米），联调用
         "feeders": ["负一层门厅照明"]  // 下挂负载，仅档案展示
      }]
    ]
  }]
}
```

校验规则（`node scripts/check-power-rooms.mjs`）：code 房内唯一、model 必须 4 枚举之一、devCode 须两位字母+6位、nudgeX 数字、id 全局唯一。

## 六、从旧项目继承的规矩（用事故换来的，别丢）

1. **编号对接只做精确匹配**——福永曾因模糊匹配把高压柜错绑到别的柜并改名。
2. **查无即报错**——旧代码查不到回路定义时静默用第一份顶替，出问题无从排查；新项目任何「查不到配置/模型/编号」必须显式报错。
3. **告警不涂柜身**——柜体保持原色，用半透明呼吸光罩 + 指示灯表达告警（浅底上才显眼）。
4. **结论以运行时为准**——旧项目图纸常量与运行时合并产物不一致曾导致误判；对拍/验证一律取运行时输出。
5. **换模型文件必须改 URL 版本号**（如 `?v=20261028`），否则浏览器缓存旧模型。
